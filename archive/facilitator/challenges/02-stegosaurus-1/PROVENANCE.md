## Why reuse canonical bytes instead of regenerating

The archive ships `main/Challenge 2/genstring.py`, the generator that produced the
201 filler lines (lines 2–202) of the payload. It calls Python's `random` module
**without seeding** (`random.choice` / `random.random` with no `random.seed(...)`),
so every run yields a different file. There is therefore **no way to reproduce the
canonical `Flag 2.txt` byte-for-byte**, and re-embedding freshly generated filler
would change the payload hash *and* destroy the deliberately planted Challenge 3
ciphertext on line 9.

**Decision:** rebuild by **re-using the canonical archived `stego_badger.jpeg`
bytes** (a straight copy from the archive), not by regenerating the payload and
re-embedding. This is the pattern mandated by `build/DIRECTORY_CONTRACT.md`
("Where the archive used an unseeded generator (C2 `genstring.py`), rebuild by
re-using the archived canonical bytes rather than regenerating, and say so here").
